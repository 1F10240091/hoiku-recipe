## 1. アプリの概要（1.5分）

### テーマ：少子高齢化への対抗 — 子育て世帯の負担軽減

**社会の現実**
- 2025年の出生数は約 **67万人**（過去最少）
- 合計特殊出生率は **1.14**（過去最低）
- 子育て世代の **42.5%** が「自分の時間が取れない」ことに悩んでいる
- 子どもを持つ家庭は、持たない家庭に比べて家事・育児の時間が
  **1週間で約13時間／1ヶ月で約55時間／1年間で約28日分** 長い

**ボトルネックは「毎日・休みなし」の食事準備**
- 食事管理は毎日発生する家事で、保護者の負担の代表
- とくに **偏食** と **アレルギー** は、献立の意思決定を重くする
- 「今日は何を作ろう」の連続が、保護者の時間と心の余裕を奪っている

> **私たちの立場**：少子化は「産む・産まない」の選択だけの問題ではない。
> **子育て世帯の日常の負担を減らすこと**が、少子高齢化への具体的な対抗策になる。

### サービス概要

**ほいくレシピ** は、保育園の献立表を読み取り、園の昼食と重ならない夜ごはんを自動提案するサービス。

1. 園の**献立表をアップロード**（OCR）
2. お子さんの**アレルギー・好き嫌い**を登録
3. **ボタン1つ**で提案
4. 献立 → レシピ → **買い物リスト**まで一気通貫

**対象**：保育園に通う 3〜6 歳児を持つ共働き世帯

### 社会的意義（リリースの狙い）

- 食事準備の**時間的・精神的負担**を軽減し、仕事と育児の両立を支える
- 毎日の負担を減らし、**子育てしやすい社会づくり**に貢献する
- 国が推進する少子化対策（こども家庭庁「**こどもまんなか社会**」）の方向性に沿う

## 3. 問題点・改善点（1.5分）

優先度の高い順に。

1. **AI 献立生成は実装済みだが、API キー未設定**
   年齢適応の自由生成・アレルギー除外・レシピ自動登録まで実装済み。実キーでの精度検証だけが残っている。現在はルールベースに自動フォールバック。
2. **OCR の精度とばらつき**
   AI 画像認識で改善したが、手書き・薄い文字・園ごとのフォーマット差は残る。失敗時はテキスト抽出へ自動フォールバック。
3. **「重複回避」が主菜ベース**
   現状は主菜の重複を避ける実装。副菜・汁物や“食材レベル”の重複には未対応。
4. **本番DB・デプロイ未実施**
   開発は SQLite のまま。Supabase（PostgreSQL）移行と公開が未完了。
5. **テストがバックエンド中心**
   API テストは厚いが、フロントの E2E テストは未整備。
6. **ドキュメントが実装と乖離**
   ユーザーマニュアルに古い記述（フィードバック画面・アレルギー自由入力など）が残っている。
7. **開発環境の自動リロードが不安定**
   OneDrive 配下で WatchFiles の自動リロードが効かず、手動再起動が必要になることがある。
8. **パフォーマンス／アクセシビリティ未計測**

**事業面の課題**
- 園ごとの献立表フォーマットの差（導入時のハードル）
- 「使い続けてもらう」動機づけ（習慣化）
- 子どもの情報を扱ううえでの個人情報の配慮
