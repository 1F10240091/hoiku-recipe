# ほいくレシピ 現在の実装状況

> 2026-10-28時点のコードと、リポジトリ内の2026-10-27公開品質チェック記録に基づく。チェック結果の再実行はしていない。

## 技術構成

| 項目 | 現在の実装 |
|---|---|
| フロントエンド | Next.js 16.4.3 / React 19.3.1 / TypeScript |
| ランタイム | Node.js 20.19以上（Vercelでは22.x推奨）、Python 3.12 |
| API | FastAPI / SQLAlchemy |
| 開発DB | SQLite |
| 本番DB | PostgreSQL必須。DBリリースコマンドとAlembicあり |
| 献立表解析 | Gemini API。`GEMINI_API_KEY` が必要 |
| 献立提案 | 登録済みレシピを使うルールベース選定 |

## 実装されている機能

- アカウント登録・ログイン、JWT認証、リクエスト制限
- 子どもの登録、月齢情報、29品目のアレルゲン候補と自由入力、好き嫌い
- 献立表のアップロード。PDF/PNG/JPEG/WebP、最大4MB、PDFは既定で最大5ページ
- 登録済みレシピから1〜7日分の夕食を提案
- レシピ検索・投稿・編集・公開設定・お気に入り・提案内の「喜んでた」記録
- レシピ写真の検証・WebP変換・PostgreSQL保存。写真なしは料理イラストを表示
- 在庫と買い物リスト
- アレルゲンと関連食材の共有カタログ
- SQLiteを使うローカル開発と、APIなしのブラウザ内デモモード
- `seed_data.py` にシードレシピ100件（うち77件に参照URL）

## 仕様と限界

- 夕食提案はAIが新規レシピを生成せず、公式・公開レシピと本人の投稿から選ぶ。
- 月齢、アレルギー、好き嫌いの「除外」、在庫、園献立、前日の提案を参照する。「改善優先」は提案結果に反映されない。
- 昼食との重複回避は主菜名を中心にした簡易判定で、食材単位の重複回避ではない。
- アレルゲン照合は共通カタログ・関連語・レシピの食材名と任意の原材料記録を使う。未記録の製品原材料は分からず、安全を保証しない。
- 献立表解析はGeminiのみ。キー未設定や解析失敗時の別OCR・テキスト抽出への自動フォールバックはない。
- 献立表解析結果の日付が空の場合、現在の保存処理は今日の日付を使う。取り込み後に確認が必要。
- 買い物リストは直近7件の提案を対象にし、同名・同単位の数量を合算。在庫数量は差し引かず、材料名の部分一致で除外する。
- 投稿レシピは初期状態で非公開。投稿者が公開設定を変更できる。
